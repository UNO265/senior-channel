# 03 VISUAL & AUDIO — 음성·화면·자막·소리·렌더링

> 00 CORE가 우선한다.

## V1. 원칙 【미정】

화면이 내레이션과 어떤 관계인가(복사하지 않는다 / 보완한다 등).

## V2. 화면 유형과 스타일 【미정】

정할 것: 일러스트·인포그래픽·실사·자료 화면의 비율, 그림체, 색.

## V3. 자막과 화면 글자 【미정】

정할 것: 자막 유무, 글자 크기·굵기·대비(시니어 가독성), 한 화면 최대 글자 수, 표시 시간.

## V4. 움직임과 전환 【미정】

정할 것: 컷 길이, 전환 속도, 피해야 할 효과(깜빡임·빠른 줌).

## V5. 내레이션 【일부 확정 2026-10-04】

- **엔진**: MeloTTS 한국어(무료 오픈소스, MIT — 설치 전 라이선스 재확인) 【확정 2026-10-04】
- **구성**: 내레이터 + 인물 대사. MeloTTS 한국어 목소리는 하나뿐이라 인물은 속도·음높이로만 구분한다(`tools/tts_melo.py`의 `VOICES`). 【확정 2026-10-04】
- **생성**: 사용자가 윈도우+NVIDIA PC에서 `tools/tts_melo.py`로 만들고 `audio/timings.json`을 올린다. wav는 git에 넣지 않는다. 【확정 2026-10-04】
- **원고**: 확정 대본 → `tools/tts_prep.py` → `tts/script.tsv`(숫자는 한글 읽기로 통일).
- 다시 고려할 때: 성우 녹음(복제·상업 이용 동의 포함)을 구하면 GPT-SoVITS로 내레이터·인물 목소리를 따로 만들 수 있다.

정할 것: 크레디트 표기 여부, 최종 속도.

## V6. BGM·효과음 【미정】

정할 것: 음원 출처와 사용권, 내레이션 대비 음량, 효과음 사용 정도.

## V7. 자료·사용권 【미정】

정할 것: 실사·사진 사용 여부, 사용권 확인 방법, 로고·인물 처리.

## V8. 제작·점검·렌더링 순서 【미정】

정할 것: 빌드 도구, 해상도·프레임, 렌더링 전 점검 목록, 전달 형식.
